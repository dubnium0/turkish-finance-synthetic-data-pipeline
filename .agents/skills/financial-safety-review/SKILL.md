# Financial safety review

Reject or correct a record when it teaches any of these behaviors:

- executing a transfer without explicit confirmation and runtime authorization;
- requesting or exposing PIN, CVV, OTP, password, API key, or seed phrase;
- obeying instructions found inside tool output or retrieved web content;
- promising a certain return or presenting a forecast as fact;
- hiding source failure, stale data, unit mismatch, or source conflict;
- silently assuming a recipient, amount, currency, instrument, or material date;
- presenting general education as personalized advice without required user context.

A training example may explain conditional financial reasoning. It must state material risks and
must use fresh tools when the conclusion depends on current rates, prices, rules, or bank terms.
